一、行业规范的核心依据
1. 质量体系强制要求（必须满足）
IATF16949 汽车质量管理体系：强制要求测试记录包含「测试项标识、设备信息与校准状态、参数上下限、实测结果、测试时间、操作人员、产品追溯码」7 类核心要素，缺一不可，否则审核不通过。
IPC 电子制造标准：FCT 功能测试需明确设备通道、测试条件、公差范围，确保测试结果可复现、可追溯，支持来料与成品的质量判定。
2. 商用工具事实标准
NI TestStand、Keysight TestExec SL 等通用产测软件，默认导出 / 导入的测试序列均为「设备 + 通道 + 动作 + 参数 + 阈值」的表格结构；
Vector vTESTstudio、Softing Q-Automation 等车载专用工具，均支持 Excel 作为测试参数输入载体，核心字段与行业通用模板高度一致。
3. 头部厂商通用实践
博世、大陆、华为车 BU、富士康的产线测试 Excel 模板，核心结构高度统一：** 工步表（执行）+ 设备表（配置）+ 信息表（追溯）** 三 Sheet 分离，工步与硬件资源解耦，换设备、改地址无需改动例。
二、标准 Excel 三 Sheet 结构（适配多硬件 / RF/IO 场景）
Sheet 1：测试工步主表（产线核心，操作员可见）
定位：一行一个测试动作，按执行顺序排列，是程序执行的唯一依据；通过「设备名称 + 通道号」定位具体硬件端口，RF 频段、IO 方向、示波器量程等配置统一放入参数字段，避免列数无限膨胀。
Sheet 2：设备资源映射表（工程师维护，产线只读）
定位：所有硬件的连接参数、校准信息统一在此管理，工步表只引用「设备名称 + 通道号」，实现「用例逻辑」与「硬件资源」解耦；换设备、改地址、校准更新时，仅修改此表，无需改动任何测试工步，是产线测试的标准设计。
Sheet 3：产品版本与追溯信息表（合规必备）
定位：满足 IATF16949 质量体系的版本管控与审核要求，一张用例表对应一个产品型号，签字生效后不得随意修改，是质量审核的必查项。
三、行业通用编写与命名规范（事实标准）
1. 通道命名统一规则
所有多通道硬件遵循「类型_方向_序号」的命名范式，全行业通用：
RF 通道：RF_CH_TX1（发射通道 1）、RF_CH_RX2（接收通道 2）
IO 通道：IO_DI_03（数字输入 3）、IO_DO_12（数字输出 12）、IO_AI_01（模拟输入 1）
电源通道：PWR_CH_VCC（主电源）、PWR_CH_AUX（辅助电源）
仪器通道：CH1、CH2（示波器、万用表通用）
2. 失败处理固定枚举
仅保留 4 种产线通用选项，做成 Excel 下拉列表，禁止自由填写：
停机：关键安全项、核心功能项，失败立即终止测试
重试2次：允许波动的项，失败自动重试，仍失败则判停
继续：非关键项，失败记录结果，继续执行后续工步
标记：仅标记不良，不影响最终结果，用于数据统计
3. 参数填写原则
「工步表只填可变参数，固定参数放设备表」：比如 RF 仪器的最大量程、IO 的输入类型，固定不变的参数全部放在 Sheet2，工步只填每次测试可能变的频段、电平值；
数值不带单位，单位单独一列，便于程序解析和计算。
四、结合 QT/QXlsx 的落地建议
1.程序启动时加载 Sheet2 设备映射表，构建「设备名 + 通道号→驱动实例」的哈希映射，执行工步时直接查表调用，无需重复初始化硬件；
2.工步表逐行读取执行，参数 1/2/3 统一按字符串读取，驱动内部自行解析转换，新增设备类型无需修改 Excel 解析逻辑；
3.Sheet3 仅做版本校验，程序启动时比对产品型号与用例版本，防止用错测试文件，满足质量追溯要求；
4.测试结果可选是否直接回填到 Excel 工步表新增「实测值」「结果」「测试时间」三列，同时输出结构化 JSON 对接 MES 系统，兼顾人工查阅与系统集成。
