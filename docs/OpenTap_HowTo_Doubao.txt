核心结论
DUT、Instrument、TestStep 是 OpenTAP 的三类核心插件：DUT 是被测对象、Instrument 是测试仪器、TestStep 是执行动作；前两者属于「资源类」，后者是「执行单元」。
OpenTAP 原生支持多 DUT 测试，支持串行、并行、一发多收等多种模式，靠并行步骤容器 + 多资源引用实现。
OpenTAP 本身没有「CELL（测试单元 / 工位）」的内置概念，CELL 是产线工程术语；落地时既可以用单进程并行分支模拟多 CELL，也可以每个物理工位跑独立 OpenTAP 实例，量产线普遍用后者做物理隔离。
一、DUT / Instrument / TestStep 的明确区分
从 OpenTAP 官方插件类层级可以清晰看到三者的定位差异OpenTAP：
根接口：ITapPlugin（所有插件的基础）
Resource（资源类，自带生命周期管理）
DUT：被测设备
Instrument：测试仪器
TestStep：测试步骤（直接继承根接口，不属于资源）
1. DUT（Device Under Test，被测设备）
定位：测试的目标对象，继承自Resource基类，是被测产品的软件抽象。
核心特性：
自带Open()/Close()生命周期方法：测试计划启动前自动并行打开（建立通信、初始化 DUT 状态），测试结束后自动复位到安全状态并关闭连接OpenTAP。
可自定义属性与方法：比如 DUT 的序列号、固件版本、供电控制接口、业务指令下发接口等，所有和被测件相关的控制逻辑都封装在这里。
对应你的场景：车载 ECU、域控制器、5G 模组等待测试产品，每个 DUT 有唯一 ID，测试结果和数据全程与 DUT 绑定追溯。
多 DUT 支持：一个测试计划里可以同时注册多个 DUT 对象，供测试步骤按需调用。
2. Instrument（测试仪器）
定位：执行测试的工具设备，同样继承自Resource基类，是测试硬件的软件抽象。
核心特性：
同样遵循Open()/Close()生命周期：测试前自动连接仪器、配置初始参数，测试后复位到安全状态OpenTAP。
官方内置ScpiInstrument子类，原生适配所有符合 SCPI 标准的仪器（可编程电源、示波器、信号发生器等）。
对应你的场景：IT7800 电源、N5182B 射频仪、CAN/LIN 分析仪等测试硬件。
资源复用性：一台仪器可以被多个测试步骤复用，也可根据设计共享给多个 DUT（比如单台大功率电源同时给多个 DUT 供电）。
3. TestStep（测试步骤）
定位：测试执行的最小功能单元，是组成测试计划的基本块，不属于资源类。
核心特性：
必须实现Run()方法：步骤执行时的核心逻辑，比如 “设置电源输出 12V”“读取 DUT 工作电流”“判定测试项 Pass/Fail” 都在这里实现OpenTAP。
通过属性绑定 DUT 和 Instrument：执行时调用对应资源的接口完成动作，自身不直接操作硬件。
支持嵌套子步骤：可以组成循环、条件分支、并行容器等复杂流程控制结构。
对应你的场景：每一个具体测试项，比如 “上电自检”“DoIP 通信测试”“电压精度测量” 都是一个独立的 TestStep。
三者的协作关系
测试计划启动 → 并行打开所有用到的 DUT 和 Instrument → 按流程执行每个 TestStep → Step 调用绑定的 DUT/Instrument 完成操作 → 全部执行完毕后并行关闭所有资源 → 输出结构化测试结果。
二、多 DUT 测试的实现方式
OpenTAP 原生支持多 DUT 测试，官方定义了 4 种典型架构，从纯串行到全并行都可实现，核心靠「并行步骤容器」和「多资源引用」完成OpenTAP。
1. 四种官方标准模式
模式 1：串行轮询（Ping-Pong）
逻辑：DUT1 全套测试完成 → 切换到 DUT2 执行全套测试
适用场景：仪器资源有限，一套仪器轮流测多个 DUT；产线人工上下料场景，一个 DUT 测试时操作员更换另一个
实现方式：单测试计划内循环切换 DUT 资源，依次执行全套测试步骤
模式 2~4：并行混合模式
一发多收：一台发射仪器发出信号，多个 DUT 同时进入接收状态，接收仪器轮流采集每个 DUT 的测试结果；适合射频、通信类批量测试
全并行测试：每个 DUT 配备独立的全套仪器，测试流程完全同步执行；适合多通道治具、高产能产线
实现方式：用Parallel并行步骤容器，每个分支对应一个 DUT 的测试流程，分支内的资源互相隔离
2. 底层技术支撑
Parallel 并行步骤：OpenTAP 基础插件自带的容器型步骤，所有子分支会在独立线程中同时执行，是多 DUT 并行测试的核心实现方式。
资源并行初始化：所有 DUT 和仪器的Open()方法默认并行执行，大幅减少多设备场景的初始化耗时。
单步骤多 DUT 支持：一个 TestStep 可以绑定多个 DUT 对象，实现批量下发指令、批量采集数据，减少重复代码。
三、关于「CELL（测试单元 / 工位）」的说明
1. 原生层面：无 CELL 内置概念
OpenTAP 核心引擎里没有 CELL 这个原生定义，CELL 是工业测试产线的工程术语，指一套独立的测试工位 / 测试单元（包含独立的 DUT、仪器、治具、执行机构）。
2. 工程落地的两种实现方式
单进程多 CELL（同工位多通道）
实现：一个 OpenTAP 测试计划内，用 Parallel 容器分出多个分支，每个分支对应一个逻辑 CELL，绑定独立的 DUT 和专属仪器
适用场景：同一块治具上同时测试多个 DUT（比如多连板测试），物理位置集中，统一管控
注意事项：如果有共享仪器，需要加锁避免资源冲突；全独立资源则无影响
多进程多 CELL（量产线标准方案）
实现：每个物理测试工位（CELL）运行一个独立的 OpenTAP 进程，加载各自的测试计划和资源配置，互相完全隔离
适用场景：量产线多个独立工位，每个工位有自己的治具、仪器、上下料机构
优势：隔离性最好，一个工位故障不影响其他工位，运维和扩展最简单，是工业量产的主流方案
补充
OpenTAP 不会强制你拆分 CELL，完全由硬件资源和产线布局决定。如果是单治具多 DUT 验证测试，用单进程并行分支最方便；如果是产线多个独立工位，每个工位跑一个独立实例是最稳妥的方案。
