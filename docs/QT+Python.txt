QT/C++ + Python 产线测试框架 完整架构总结
本方案面向多硬件联动的产线 FCT/EOL 测试场景，对标 NI TestStand 等商用平台的分层设计理念，完全匹配你提到的多电源、RF 仪器、示波器、万用表、CAN、IO 板卡等硬件资源，同时满足 IATF 16949 质量体系可追溯、高可靠的合规要求。
核心设计三原则：
1.QT 唯一主控：流程调度、硬件管控、结果判定、数据归档全由 QT 统一负责，是系统稳定的基石
2.Python 插件化：仅承担「算法计算、设备代理」两类扩展职责，不碰核心流程，崩溃不影响主系统
3.Excel 单一用例入口：所有测试工步、参数、阈值仅由 QT 解析加载，Python 全程不接触业务文件

二、Excel 测试用例标准结构（3 核心 Sheet，QT 唯一解析）
Excel 是测试业务的唯一输入载体，全程仅由 QT 解析加载到内存，Python 完全不读取、不修改 Excel 文件，避免文件冲突与流程失控。
Sheet 1：测试工步执行表（产线核心）
定位：程序执行的唯一依据，一行对应一个测试动作，按执行顺序排列
核心字段：工步号、设备分类、设备名称、通道号、测试项名称、动作指令、配置参数 1/2/3、判定下限、判定上限、单位、超时 (ms)、失败处理、备注
特点：业务人员可见可编辑，不感知底层是 QT 驱动还是 Python 驱动
Sheet 2：设备资源映射表（工程师维护）
定位：硬件资源统一管理，实现「测试逻辑」与「硬件资源」解耦，换设备、改地址不用改动例
核心字段：设备分类、设备名称、通道号、连接方式、地址 / 端口、设备型号、资产编号、校准有效期、驱动实现方（QT 原生 / Python 插件）、启用状态
关键作用：QT 启动时构建路由映射，执行工步时自动选择对应驱动方式
Sheet 3：产品追溯信息表（合规必备）
定位：满足质量体系版本管控要求，一张用例表对应一个产品型号，签字生效后受控
核心字段：产品型号、用例版本号、标准测试节拍、引用标准、编制 / 批准人、生效日期、版本变更记录

1. 核心职责总分工

测试流程调度、工步顺序、跳转重试	✅ 统一管控	❌ 不参与

2. 两类设备驱动的执行模式
模式 A：QT 原生驱动设备（主流硬件，90% 场景）
电源、CAN、IO 板卡、主流示波器 / 万用表等有成熟 C++ 驱动的设备，QT 直接控制硬件，Python 仅按需做算法扩展。
完整流程：
QT 解析 Excel，初始化硬件，加载全部工步到内存
执行到对应工步时，QT 直接发指令控制硬件，采集原始数据
若需复杂计算（如纹波、频谱分析），QT 将原始数据 + 参数打包为 JSON，通过 QProcess 调用 Python 算法插件
Python 完成计算，返回结果 JSON
QT 拿到结果，与 Excel 中的阈值比对，统一判定 PASS/FAIL，记录日志
模式 B：Python 代理驱动设备（小众 / 非标硬件）
仅厂商提供 Python SDK、无 C++ 驱动的设备（如定制 RF 仪、特殊治具），Python 仅作为单步执行代理，流程管控仍在 QT 侧。
完整流程：
QT 解析 Excel，从设备映射表识别到该设备为「Python 插件驱动」
执行到对应工步时，QT 将「设备名 + 通道 + 动作 + 参数 + 超时」打包为 JSON，调用对应 Python 驱动脚本
Python 调用厂商 SDK 操作硬件，采集数据后返回结果 JSON
QT 统一接收结果，比对 Excel 阈值，执行失败处理逻辑（重试 / 停机 / 继续）
若 Python 超时、崩溃，QT 直接终止进程，按规则兜底，保障硬件安全
3. 测试报告分工
单产品原始测试记录：QT 直接生成（回填 Excel 模板），作为合规存档依据，保证数据可追溯、不可篡改，满足质量体系要求。
批次分析与定制报表：QT 汇总批次原始数据后调用 Python，生成 SPC 控制图、CPK 分析、不良分布统计、带波形的失效分析报告，发挥 Python 生态优势，应对频繁变动的报表需求。
四、不可突破的产线设计红线
以下职责必须牢牢掌握在 QT/C++ 侧，绝不下放给 Python，是量产场景的可靠性与合规性底线：
安全相关：急停响应、安全门检测、过流过压保护、硬件紧急下电，必须由 C++ 硬实时处理，Python 无法保障毫秒级可靠性。
流程相关：工步调度、超时控制、失败重试、分支跳转，必须由 QT 统一管控，避免脚本异常导致流程混乱。
判定相关：最终 PASS/FAIL 判定、原始测试数据归档，必须由 QT 输出，保障测试数据的权威性与可追溯性，满足 IATF 16949 审核要求。
配置相关：Excel 用例、设备配置、系统参数，只能由 QT 统一解析加载，禁止 Python 直接读取业务配置文件。
五、落地技术选型清单
QT/C++ 侧
Excel 解析：QXlsx（纯原生，无需安装 Office）
JSON 处理：nlohmann/json 或 Qt 原生 QJsonDocument，配合 JSON Schema 做格式校验
进程调用：QProcess，配合标准输入输出实现 JSON 双向通信
硬件驱动：SCPI 通用指令库 + 各厂商 C++ SDK + 自定义设备抽象接口
Python 侧
信号算法：numpy、scipy（滤波、FFT、统计计算）
射频分析：scikit-rf（RF 参数计算）
报表生成：pandas（数据统计）、matplotlib/plotly（图表）、openpyxl（复杂格式 Excel）
设备代理：对应厂商 Python SDK、pyvisa（通用仪器控制）
通信协议
采用标准 JSON IPC 协议，遵循你之前确定的 Schema 规范，包含消息 ID、指令、数据、状态码、时间戳等字段，保证跨语言交互一致性。
六、落地推进建议
第一阶段：完成 QT 核心引擎 + Excel 三 Sheet 解析 + 主流硬件原生驱动 + 基础测试流程，先跑通核心产测功能，保证稳定性。
第二阶段：接入 Python 算法插件，实现波形分析、纹波计算等复杂数据处理，补充报表能力。
第三阶段：按需接入 Python 代理驱动，兼容小众 / 非标设备；扩展批次统计、MES 对接等功能。
这套架构是汽车电子、工业电子量产测试的行业标准实践，既守住了产线可靠性、合规性的底线，又通过 Python 插件保留了足够的灵活性与扩展能力，平衡了开发效率与系统稳定性。
